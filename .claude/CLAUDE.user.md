## 工作风格

- 优先改现有文件,不要随手新建文件或文档。
- 不写解释 *what* 的注释 (代码自己会说);只在 *why* 不明显时加一行短注释。
- 改 bug 就改 bug,不要顺手重构、加抽象、补"未来可能用到"的扩展点。
- 不要为内部代码补防御性校验和回退分支;只在系统边界 (用户输入、外部 API) 做检查。
- 销毁性操作 (rm -rf、git reset --hard、force push、删分支/表) 先确认再动。

## 当前研究方向

我**不是 SANDO 的开发者**。SANDO (MIT-ACL 的轨迹规划基线,ROS 2 Humble) 是我研究的**基线**;我在它之上开发新算法 (这条线在 Python `sando-py` 迭代,C++ `sando_ws/src/sando` 是基线本体),目标:
1. **提升效果** —— 比 SANDO 跑得更好。具体优化维度 (2026-05-29 拍板): ① 动态反应性 (在正确时刻躲动态障碍,尤其人) ② 可解释性本身当 paper 卖点 ③ 安全裕度/成功率 ④ 轨迹质量。定位 = 博士主线完整新框架,顶会为目标。
2. **继承可解释性** —— 不能换成黑盒,要保留 SANDO 那种"每一步都看得见为什么"的结构(heat-map A* / 显式场或约束 / 显式优化器 / 清晰状态机)。

当前算法骨架 (取代 SANDO 的 Gurobi/MIQP/凸走廊): 全局 heat-A* 向导 → 局部 **MINCO** 曲线 + **per-class 差异化避障** (人 = 凸包+ALM 硬约束、墙 = EGO 软场,由障碍类别决定用哪套) + 解析梯度优化。因此当我说"改 SANDO"通常指**基于 SANDO 做新算法**,不是 patch 上游。
